# Browser compiler expansion: verified scope

The JavaScript modules are pure browser ES modules. They take byte maps and the existing isolated Wasm Clang session. No filesystem, Python, server compiler, SDK download or arbitrary project build hooks execute in the browser pipeline.

`buildPebbleApp({sourceFiles,sdkFiles,session,projectRoot,platform='emery',bundledJs,timestamp,log})` builds one selected platform. `bundledJs` is the caller's already-resolved JavaScript bundle; it permits JS package dependencies and still receives the SDK shared additions. Native C package libraries are not resolved by this option. `normalizeMessageKeys` is exported for the bundler's `message_keys` module.

Verified platform builds: aplite, basalt, chalk, diorite, emery, flint and gabbro, using each platform's actual SDK headers, API library, feature defines, memory limits, resource limits and PBLAPP platform flag. Flint/Gabbro demo builds were installed into unchanged v4.37 firmware and matched the entire official native-QEMU framebuffer in independent native-QEMU comparisons. This does not establish hardware emulation for older platforms; compilation and firmware hardware coverage are separate gates.

Resource support: PNG, PBI, PBI8, PNG transparency masks, bitmap memory/storage options, raw bytes, aliases, targetPlatforms filtering, most-specific `~tag` filename selection, menu icons, generated RESOURCE_ID constants, deduplication and official app-resource pack serialization. Resource IDs preserve selected media order. PNG decoding supports Adam7, filters0–4, palette/grayscale/RGB/alpha, legal1/2/4/8/16-bit depths, tRNS and sBIT handling. PNG conversion intentionally ignores sBIT like png2pblpng.py; PBI honors it like bitmapgen.py. Image decoding is bounded to4,194,304 pixels and32767px per dimension. Resource count limit256; platform pack-size limit enforced.

The implementation preserves SDK peculiarities needed for byte parity: the4092-byte empty resource pack, reversed deduplication assignment to ensure the final table entry ends at pack EOF, STM32 partial-word CRC ordering, CPython3.11 integer-set palette ordering, and bitmapgen's asymmetric cropped-right calculation. Malformed/empty crop results reject explicitly.

Legacy `appinfo.json` native SDK3 projects and C files under `src/` compile. Modern `package.json` uses `src/c/`. Array messageKeys allocate blocks first, then scalar keys, starting10000; explicit numbered dictionaries remain unchanged. Invalid uint32 ranges and duplicate keys reject. Supported standard wscript templates are recognized without executing Python. Unsupported/custom wscript logic remains an explicit error.

Unsupported: custom font generation, SVG rasterization, built-in/published library resources, native C package dependencies, custom Python/Waf/shell steps, C++/assembly, SDK2, Moddable/PebbleJS projects and arbitrary compiler SDK versions. PNG-trans aliases are rejected because the SDK duplicates aliases across its two generated resources; use explicit PBI definitions. Background workers under worker_src/c are compiled with the SDK worker memory limit, packaged and installed; a firmware launch/log acceptance gate passes.

## Browser bundling and package inputs

The compiler Worker always parses and bundles an existing PKJS entry with self-hosted esbuild-wasm
0.28.2. Local CommonJS/ES modules and JSON use a bounded in-memory filesystem. `message_keys`
uses the same SDK allocator as C headers. The phone runtime is modern QuickJS; this does not
promise that every modern JavaScript feature is supported by historical physical-phone engines.

Dependencies require package-lock.json v2/v3 matching package.json. Downloaded registry.npmjs.org
tarballs must pass SHA-256/384/512 integrity, compressed/expanded limits and safe-path checks.
No npm script or custom repository plugin executes. Ordinary JS packages follow their declared
entry. Pebble packages use the SDK alias to the published dist.zip's dist/js artifact; native
libraries, resource libraries and package-owned key merging still require a separate build profile.

The existing `examples/watchface` remains the frozen direct-builder reference. The browser
Worker now bundles even single-file scripts, so its JavaScript wrapping can differ from that
older reference's PBW bytes. `examples/platform-watchface` exercises the current module pipeline.

## Linux compatibility backend

Projects can provide `.pebble-browser.yml` and an imported container2wasm WASI image. The
Angular workbench launches a disposable Worker with a Linux VM, isolated source/dependency
mounts, bounded Wasm memory and files, a parent-enforced timeout, and explicit artifact
outputs. Commands run on the guest POSIX filesystem. Cancellation terminates the Worker even
if an untrusted program never yields. No host shell, filesystem handles, account credentials,
network device or CORS proxy are exposed to the guest.

This backend has run real Python generation and Linux ARM GCC 12.2.0 and returned an ARM
EABI5 object. It has **not** passed a complete SDK/Waf-to-PBW workflow. Importing an arbitrary
repository still does not establish compatibility: its SDK, fonts, compiler, native libraries,
Python/Node versions and dependencies must be present and verified. Python 2 and legacy SDK
images remain pending. The optional Docker image preparation recipe is unverified and does
not include proprietary SDK blobs. See [image and recipe instructions](../tools/linux-build/README.md)
and [the execution/provenance record](evidence/linux-build-gate.json).

Local folder import accepts up to 20,000 files / 128 MiB, excluding node_modules
and .git directories. Build and .github directories are preserved because they can contain
required source scripts. GitHub snapshots retain their separate bounded import behavior and
commit identity. Git submodules/LFS, POSIX source modes and custom dependency acquisition need
further work; resolved local files are the current fallback.
